## Completed accelerator arbitration and runtime OOM recovery

- **WHAT:** Added typed engine failure classes, explicit auto versus CPU-only backend policy, broker-owned accelerator lease state, permanent CPU demotion, one retry, and health reporting for lease/degradation state.
- **WHY:** Multiple broker instances must never multiply accelerator residency, and a 6 GB Windows NVIDIA system must recover deterministically when runtime VRAM pressure exhausts the active backend.
- **HOW:** Only typed context-allocation failures are resource exhaustion. An accelerated broker holding the lease drops the engine before the lease, reloads with `CpuOnly`, records permanent degradation, and retries once. CPU exhaustion and ordinary failures do not retry. Reload failure becomes terminal.
- **IMPACT:** Task 6 of the shared semantic broker plan is locally complete and unblocks Miller connect-first/spawn-on-demand supervision.
