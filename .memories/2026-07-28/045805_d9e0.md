## Implemented the Windows shared semantic broker transport

- **WHAT:** Added a platform-neutral broker transport seam, overlapped Windows named-pipe listener/connections, current-user-only ACLs, remote-client rejection, cancellation-safe operation ownership, Windows lifecycle tests, and a Windows CI job before conformance.
- **WHY:** Multiple Miller processes must share one semantic sidecar on Windows without duplicating GPU model residency, leaking handles, leaving stale cleanup state, or recreating the unreliable Julie daemon design.
- **HOW:** Used exact `windows-sys 0.61.2` bindings with pinned `OVERLAPPED` state, one manual-reset event per operation, `CancelIoEx` plus `GetOverlappedResult` drain for pending work, aligned token/ACL storage, and one named-pipe instance per client. Grok review found and drove fixes for immediate-success handling and last-error clobbering under cancellation.
- **IMPACT:** The sidecar now has real Unix and Windows broker adapters behind one small connection seam. Unix behavior remains green; Windows code/type metadata is compile-checked locally and has a dedicated runtime CI gate.
