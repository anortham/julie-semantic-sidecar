## Implemented broker accelerator recovery

- **WHAT:** Added the Task 6 accelerator lease and typed OOM-to-CPU recovery implementation.
- **WHY:** Concurrent semantic brokers must not multiply accelerator memory use, and runtime VRAM exhaustion must recover without a broker restart loop.
- **HOW:** The broker owns a single accelerator lease, drops the accelerated engine before releasing that lease, reloads under a CPU-only policy, and retries a typed resource-exhaustion failure once.
- **IMPACT:** The implementation was ready for lead review, focused verification, and model-backed testing.
