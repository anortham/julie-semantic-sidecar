## Fixed Windows broker cancellation retry loop

The first Windows CI run revealed a real production cancellation bug beneath the test hang.

- **WHAT:** Preserve raw Win32 `ERROR_OPERATION_ABORTED` from overlapped pipe operations and restore the production-style `write_all` cancellation regression.
- **WHY:** `io_error` converted error 995 to `ErrorKind::Interrupted`; Rust `Write::write_all` is required to retry `Interrupted`, so it started another large pipe write after the one-shot cancellation had been consumed and blocked forever.
- **HOW:** Removed the custom `Interrupted` remap. Pinned Rust 1.97.1 maps raw Windows error 995 to non-retryable `TimedOut` while retaining `raw_os_error() == Some(995)`. All three cancellation tests now assert the exact Win32 code.
- **IMPACT:** Production broker replies and other `write_all` callers terminate promptly after cancellation instead of silently reissuing I/O. The Windows regression proves the caller-facing behavior rather than only a single `WriteFile`.
