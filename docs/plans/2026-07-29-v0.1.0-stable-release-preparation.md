# v0.1.0 Stable Release Preparation

**Goal:** Turn the verified RC5 source into a stable `v0.1.0` candidate whose shipped metadata,
documentation, supply-chain gates, and local Apple arm64 artifact evidence are internally
consistent.

**Architecture Quality:** No architecture impact. This work changes release metadata,
documentation, package contents, and CI policy without changing runtime behavior or the frozen
wire contract.

## Task 1: Stable release identity and public documentation

**Files:**

- Modify: `Cargo.toml`
- Modify: `Cargo.lock`
- Modify: `README.md`
- Create: `docs/release-notes/v0.1.0.md`
- Modify: `tests/package_manifest_tests.rs`

**Steps:**

1. Change the package version to `0.1.0`.
2. Replace prerelease-only README language with an accurate stable-candidate support boundary.
3. Add publication-neutral stable release notes that do not claim a tag or artifact exists before
   publication.
4. Update the release-document contract test first, then make it pass.
5. Run the focused package-manifest test target.

## Task 2: Workflow and dependency-update hardening
